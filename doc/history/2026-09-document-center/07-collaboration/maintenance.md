# 跨对话协作与文档维护规范

> 首版：2026-09-07｜本文为文档中心的维护约定，不自动改变外部任务授权。
> [返回文档入口](../README.md) · [当前状态](../STATUS.md) · [来源索引](../08-references/source-index.md)

## 文档各司其职

| 资料 | 保存什么 | 更新方式 |
|---|---|---|
| README | 阅读路径与文档结构 | 增删专题时更新 |
| STATUS | 当前汇总状态、阻塞与下一步 | 每次关键状态变化后核对来源再改 |
| 系统/链路页 | 相对稳定的职责、语义和关系 | 架构/接口改变时更新并标版本 |
| 迭代页 | 为什么改、改了什么、验了什么 | 新迭代追加；保留旧失败边界 |
| 分支页/快照 | 代码、工作区、配套和提交差异 | 开始构建/切换任务前重新采样 |
| 操作页 | 可执行步骤、参数与前置条件 | 脚本/配置接口改变时同步 |
| sessions | 单次对话的实际结果和交接 | 一次一文件，避免多对话同写 |
| 原始证据 | Trace、日志、MCP回执、机器报告 | 保留原件；修复使用新运行身份 |

本中心是已生成的首版知识库，不表示其他对话会自动读取。新对话使用 [启动提示词](starting-prompts.md) 指定入口；更新自动化尚未创建。

## 每次对话开始

1. 阅读 README、STATUS 和本专题页。
2. 确认目标和允许修改范围，区分文档、开发、构建、采集和发布任务。
3. 涉及源码时复查目标worktree、HEAD及本次相关修改；不要把快照当实时状态。
4. 阅读本专题原始计划/验收，识别已废弃方案、未完成门禁和其他任务的资源归属。
5. 先保存本次任务ID、基线与准备修改的文件集合。

## 工作中记录的最小信息

实际动作、开始/结束时间、输入/产物身份、结果、证据路径、变化原因、剩余问题。长任务以阶段记录保证可恢复；性能推断与已验证事实分开写，不把预计结果提前填为通过。

结论采用“某版本、某输入、某配置、某层级验证通过”的表达。仅有计划就写Planned，只有单元测试就写对应层级通过。

## 对话结束

更新本专题和session记录，必要时更新STATUS、分支/工具/契约页。新增或替换来源时补 source-register/source-manifest，并保留采样日期；不要直接覆写旧运行证据。所有链接检查通过后给出固定入口和本次变化摘要。

## 多对话同时写入

优先按专题分工，不同任务各写自己的session文件。修改STATUS/README等公共文件前重新读取，只合并本任务相关行，避免整文件覆盖另一个对话的新内容。发现同一源码区域或配置被其他任务修改时先记录差异和责任范围。

本轮没有新建AGENTS.md或修改已有Skill来强制所有任务自动执行此规范。后续若要设为项目级默认规则，应单独明确规则内容与适用范围。

## 来源发生冲突时

优先比较运行身份、版本、时间和验收范围，而不机械选择日期最新文件。原始机器报告/请求响应支持事实；实施日志解释后续状态；设计表达目标。三者冲突应登记在 [待核实项](../08-references/known-gaps.md)，不静默选择更乐观结论。
