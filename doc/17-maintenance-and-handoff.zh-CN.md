# 接手步骤与文档维护

接手完成的标准是：同事能找到代码、选对工具、复现一个受控样本、解释报告边界，并知道未完成工作从哪里继续。

## 建议的接手顺序

1. 读当前状态，记录本机三仓位置、分支/HEAD、工作区差异和实际工具清单。
2. 读架构、源码地图与引擎/Package 改动；沿一个 CPU 帧、一个 GPU Pass、一个资源或 I/O 请求走完整链路。
3. 使用现有小 capture/store 核对加载、候选、事件树与原生回查；不要从重新构建整个游戏开始学习。
4. 在明确的 Player 与配置上做一轮短录制，核对实际配置、clean end 和数据域。
5. 按所选 Skill 路由生成报告，解释一个执行热点、一个等待和一个资源问题，并列出仍缺证据。
6. 核对代码构建、独立部署、回滚与当前待办，确定后续维护人和任务顺序。

## 交接材料清单

| 材料 | 应保留的内容 |
|---|---|
| 源码 | 三仓提交、必要 dirty patch/untracked 实现、外部依赖与构建入口 |
| 工具 | EXE/DLL/PDB、平台、编译配置、来源和 SHA、help/schema 回执 |
| Player | 原包身份、独立副本、代码与资源闭包、包映射、部署 manifest、运行检查 |
| 配置 | INI、实际生效回执、Skill JSON/YAML、机器路径模板与策略 |
| 样本 | 可交接小样本与代表大样本位置、原始 SHA、store schema/revision、质量 |
| 报告 | 总览、分册、原生图、源码快照、回执、审计、展示状态与启动说明 |
| 开发记录 | 历史决策、已推翻结论、待办、分支入口、验证条件 |
| 文档 | 本目录、完整变更清单、源锚点、历史归档和验证结果 |

大型 Trace、Player 和符号未随本文档复制；分享时按离线阅读、交互回查或重分析目的另行打包。

## 每次变更后更新什么

- **代码/ABI/schema**：更新当前状态、源码入口、版本矩阵与兼容说明。
- **CLI/Skill 字段或脚本**：更新对应操作页、配置示例、安装说明和产物列表。
- **数据或算法**：更新统计口径、缓存身份、候选/严重帧回归和案例。
- **Viewer**：更新定位合同、交互/响应性、DPR 和分享启动方式。
- **验收**：记录输入/工具身份、通过范围与遗留事项，不覆写旧失败为通过。
- **分支或部署**：重新采样 HEAD、dirty 状态、实际 Package 解析与二进制，不只改分支名。
