## 1. 初期基础记录（后续集成状态以上表为准）

- `TracyAnalysisCacheTable`：严格有序、不可变的记录块，固定宽度 ordinal 索引，精确 key 查找/范围起点、按字节限制分页。
- 逐块 checksum、identity/kind、版本/长度校验，manifest 最后发布；错误、取消、重复 key、超大记录不能发布成功。
- `TracyAnalysisCacheSort`：有限缓冲排序、有界 8 路合并；跨不同 run 的重复身份拒绝，不静默丢弃。已随第 7 节组合缓存完成百万级规模测试；阶段恢复仍未验收。
- `FinishToSink`：计算完成后立即交付一个 Signature 的结果，不把完整结果集合保留在内存。新 summary 类型只携带审计，不冒充完整 Aggregate；全局排名现由 `TracyNeutralStatisticsCache` 的磁盘排序构建，尚未切换默认调用方。
- 单 Signature 编码与旧全量 serializer 复用同一字段生成逻辑；小型集成已把真实统计字段写入块并定向读取核对。
- 旧 `Finish` / Query 默认路径保持原状作为对照。目前**不能把本分支当作已完成的新缓存 Query 替换日常工具**。

## 7. 2026-09-08：组合 Neutral Cache

新增 `TracyNeutralStatisticsCache`，仅作用于 Query 内部分析数据：

- 单条统计复用旧编码；Context 保留完整 payload，身份为 `(domain, signature_id, frame_scope)`。元组使用无歧义、保序的字节编码，包含 NUL/前缀字符串的回归测试。
- 统计与 Context 各自有界外排。发布前做一次顺序 merge-join：每条统计必须有关联 Context；仅明确 `frame_root=true` 的额外 Context 允许没有统计。不进行百万次单项随机查询。
- 排名按 domain/FrameSet/metric 分组，降序 total 和稳定 Signature 并列顺序；exact=false 不排名，有物理签名的作用域排除 logical，logical-only 作用域独立保留。
- 排名依次计算 inclusive、exclusive、max(wait, critical)，保留后两者分量；先顺序累加总量，再顺序生成 contribution/cumulative，沿用旧实现的舍入和末项为 1 规则。
- 统计、Context、排名、排名组都支持字节有界分页；单项精确定位不要求物化所有结果。排名分页不会越界进入下一个作用域。
- 完成 header 最后发布，绑定四个子表的计数、块数和内容身份。错误审计/计数、缺 Context、重复身份、取消均不能发布完成 header；重开时校验子表身份和索引，数据块按需校验。

红绿证据：初次实现缺失报 `neutral_statistics_cache_not_implemented`；实现后契约矩阵通过。新增审计合法性测试先报 `expected rejection: domain_audit`，补齐合法状态与摘要格式验证后通过。新增顺序 Context 分页先报 `sequential contexts include frame roots`，实现后通过。

80 签名小型旧实现 Oracle 比较统计及三类排名的全部 JSON 字段；覆盖全零作用域、分母隐式零、并列、logical-only、物理/逻辑混合和贡献小数精度。另有手写数值矩阵、错误身份、提前读取、取消、损坏块和空表测试。

### 8.1 正确性与已发现问题

小样本对比新旧实现全部候选 JSON 字段、顺序、代表证据、全部排名和 backlog，并验证 ID 查询和分页。覆盖共享家族、容量/预算/异常/用户关注、禁用优先级下的强制候选、真正竞争的全局配额、零总量签名的局部 Top、竞争失败的签名、GPU L0 区间而非 Player 帧、unknown、根时间线回退的原始顺序。

失败边界包括：物化输入、错误 Neutral 身份、缺失/不连续的 Context 原始顺序、家族预算、候选子表已发布时取消但顶层不可查询，以及从文件加载完整序列后超出帧工作区。后者先复现未检查加载后的序列，补齐检查后通过。

首次 1 万规模测试在 JSON 编码处失败，证据保留在 `build-query-analysis-cache/scale-ac3-candidate-01`，10 万未启动。根因是将任意字节排序键直接作为 UTF-8 JSON 字符串；已用 257 签名缩小复现，并改为可逆十六进制持久化。新增全部 256 种字节及序号 128 往返测试。没有忽略异常或改为丢弃非法字符。

修复后小型输入/候选缓存两项 CTest 通过（0.38 s、4.04 s）。257 签名冒烟产生 514 个候选和 771 条排名，全部分页核验通过；局部候选全部保留，全局域配额为 50。`scale-ac3-candidate-02` 的 1 万/10 万已通过，随后补充空缓存、损坏块和长序列测试。400 帧重复 Top 用例复现了预算按累计输入计费、而非保留状态计费的问题；修正后重新做全部回归与规模测试，最终证据如下。

### 最小诊断与结论边界

五个合成 Zone 可复现同类失败：

```text
L0-A [0,10]
  Good.Pass [1,2]       已作为有效物理事实输出
  Bad.Sibling [9,11]    越界，使 L0-A 无效
L0-B [20,30]
  Good.Pass [21,22]     有效
```

现有规则接收 Good.Pass 的两个 L0 观测，却只把一个有效根计入分母，得到 `present_frames=2`、`denominator=1`，明确原因 `complete_frame_denominator_smaller_than_present_frames`；默认执行器产生同类 `non_exact_signature_statistics` 错误。仅将合成 Bad.Sibling 的结束时间改为 10 后，两个根都有效、分母恢复为 2，扫描成功。输出在 `gpu-frame-scope-probe.ndjson`，复现只操作合成数据。
